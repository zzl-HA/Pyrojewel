## 电机运动（单一）

### 功能描述
能完成至少一个电机的转动

- **10月10日**：硬件链接的绝望：
  我们试图通过 ST-Link 将程序烧录进 STM32F103C8T6。但在 STM32CubeProgrammer 中，目标电压始终显示为 **0V**，并报错 `DEV_USB_COMM_ERR`。
  我们尝试了以下所有排查方法：
  1. 独立插 USB 给板子供电（红灯亮起，确认板子有电）。
  2. 对调 SWDIO 和 SWCLK 引脚（发现 ST-Link 指示灯进入闪烁状态，说明在尝试连接，但依然握手失败）。
  3. 更换了全新的 STM32 开发板，结果完全一样。
  4. 将 SWD 通信频率从 4000kHz 逐步降至 100kHz，并尝试了 Software reset 和 Hardware reset。
  5. 更换了不同 USB 数据线，确认设备管理器中存在 `STM32 STLink` 设备。
  最终我们判定：**克隆版 ST-Link 硬件本身的电压检测芯片已损坏。**

- **10月10日晚 致命漏洞排查（核心突破）**：
  烧录成功后，我们将所有硬件接线确认无误（共地、STBY使能、电源全部正常），但通电后电机依然纹丝不动。
       打开 `main.c`，逐行阅读代码学习是什么意思，意外发现了错误——**我们把控制电机转动的代码块，写在了 `while(1)` 循环的大括号外面！**
- **修正与验证**：
  我们把 `HAL_GPIO_WritePin` 和 `__HAL_TIM_SET_COMPARE` 等控制代码，移动到了 `while(1)` 循环的内部，重新编译并烧录。

### 为什么这样做（技术分析与反思）
**这是一个极其经典的 C 语言作用域错误**
单片机在执行代码时，会按顺序执行。当它执行到 `while(1)` 时，发现循环内部是空的（大括号直接闭合了），它就会永远在这里“原地踏步”，根本不会执行下面控制电机的代码。
这让我们深刻理解了 STM32 的代码执行逻辑：
- **初始化代码（如开启PWM、拉高STBY）**：必须写在 `while(1)` 外面，只需要执行一次。
- **业务逻辑代码（如控制电平翻转、改变PWM占空比、读取传感器）**：必须写在 `while(1)` 里面，实现持续不断的控制。
发现我们在排障时过度关注硬件和引脚配置，忽略了最基本的软件代码结构。

### 遇到的难点与解决方案
- **难点**：硬件链路全部正常、引脚配置完全正确、代码编译也成功烧录，但电机没有反应，让我们陷入深深的自我怀疑。
- **解决方案**：偶然机会下转向“代码结构审查”，最终定位到 `while(1)` 的作用域错误。

### 迭代优化
- 修正代码位置后，预计电机将按照设定的逻辑（转2秒停2秒）运行。
- **下一步计划**：将 PS2 手柄的读取函数接入 `while(1)` 中，用摇杆数据替换写死的速度值，实现遥控底盘运动。
